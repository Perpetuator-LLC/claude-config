# Session-Export Protocol — `#SessionSummary`

When the human tags a message **#SessionSummary** (typically because a long thread has degraded and they want a clean-context continuation), produce a complete hand-off a FRESH agent can execute without this session — the sibling of `#capture`, but for *work state* instead of knowledge:

1. **Inventory the incomplete.** Walk the whole session (and the task list) for every action item not fully done — including human-pending steps — each with enough working context (file paths, commands, order, blockers) to act on immediately. Only incomplete items get detail.
2. **Fence the settled.** List decisions made + one-line rationale as a "do not reopen" table (link the canon docs, don't restate them), and completed work as one-line pointers — so the fresh agent neither re-litigates nor re-does.
3. **Record what a fresh AI cannot infer** from repo/docs: open PRs and their update semantics, branch/worktree topology, which host runs what, live credential state, verified-catalog values, deliberate design exceptions that look like bugs (e.g. an on-box token that must NOT move to the store).
4. **Write it into the Perpetuator vault journal** — the STANDARD hand-off home (proven across orchestrator + worker hand-offs, 2026-07): append an addendum section to the current month's shared hand-off doc (`notes-perpetuator/Engagements/Internal/Journal/<YYYYMM>/thread_handoff.md`), headed `# ADDENDUM — <repo/role> <THREAD KIND> hand-off (<date>)`. The file is multi-writer and append-only: read the tail first, NEVER edit another thread's section, reconcile/correct their claims in your own addendum (⭐ Reconciliation block). Repo-local `docs/handoff/` files are the fallback only when the vault is unavailable. Do not commit the vault (sync automation owns its git).
5. **ALWAYS end with a paste-ready kickoff block — in the CHAT RESPONSE, not only inside the doc.** This is the deliverable the human actually consumes; a run that writes a beautiful addendum and forgets the prompt has failed. **Never conditional, never omitted, never "see the block in the doc"** — print it verbatim in the response every single run, even when the summary is thin, the session was a standby tick, or nothing changed. A pointer-only prompt (`Read: <path> → "<heading>"`) is a complete kickoff block; "there wasn't enough to say" is not a reason to skip it. Keep it SHORT — `Read: <journal path> → "<your addendum heading>"` + one line of goal + one line of constraints (repo, branch, gates). All detail lives in the addendum, not the prompt.
6. **Route side-captures.** Anything durable the summary surfaced (a new concept, a corrected recipe) also goes through `#capture` routing; cross-session pointers → auto-memory.
